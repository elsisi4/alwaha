# تجربة التطبيقين ونشر التحديثات

## مرة واحدة: تجهيز الأندرويد
```powershell
flutter create --platforms android,web .
dart run tool/setup_android.dart
```
السكربت يجعل لكل تطبيق معرّفًا مختلفًا (`com.alwaha.distributor` و`com.alwaha.admin`) فيُثبّتان معًا على الهاتف، ويضيف إذن الإنترنت (بدونه لا تعمل نسخة release). إن ظهرت رسالة أنه لم يجد شيئًا في ملفات Gradle فأرسل لي `android/app/build.gradle.kts`.

## دورة التجربة والتحديث
1. **ارفع الرقم** في `pubspec.yaml` (مثال: `version: 1.0.1+2`). الرقم بعد `+` هو رقم الإصدار الذي تقارن به التطبيقات، ويجب أن يكبر في كل تحديث.
2. **ابنِ الملفين:**
   ```powershell
   powershell -File tool/build_release.ps1
   ```
   تجد الملفين في مجلد `release`.
3. **ارفعهما** في لوحة Supabase: Storage ← مخزن `releases` ← Upload، ثم انسخ الرابط العام لكل ملف.
4. **انشر الإصدار** من تطبيق الإدارة: الإعدادات ← إصدارات التطبيق، واكتب رقم الإصدار واسمه والرابط وما الذي تغيّر.
5. عند فتح أي تطبيق مثبّت أقدم، تظهر نافذة "يتوفر تحديث جديد"؛ زر "تحديث الآن" ينزّل الملف، وبعد التنزيل يضغط المستخدم على الملف ليُثبَّت فوق النسخة الحالية دون فقد البيانات.

أول تثبيت يدوي: انقل ملف APK إلى الهاتف وثبّته، وفعّل "السماح بالتثبيت من هذا المصدر" للمتصفح أو مدير الملفات.

## مهم: مفتاح التوقيع
تحديث التطبيق فوق نسخته المثبّتة يشترط أن يكون الملف الجديد موقّعًا **بنفس المفتاح**. افتراضيًا يُوقَّع بمفتاح التجربة الموجود على جهازك، فابنِ كل الإصدارات من نفس الجهاز. قبل التشغيل الفعلي في المصنع أنشئ مفتاح توقيع رسميًا واحتفظ بنسخة منه، لأن تغيير المفتاح لاحقًا يجبر الجميع على حذف التطبيق وتثبيته من جديد.

## التجربة على المتصفح (بدون هاتف)
```powershell
flutter run -d chrome -t lib/main_distributor.dart --dart-define-from-file=env.json
flutter run -d chrome -t lib/main_admin.dart --dart-define-from-file=env.json
```
نافذة التحديث تعمل على الأندرويد فقط.
