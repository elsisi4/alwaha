# Al Waha — تطبيق إدارة المصنع والموزعين

مشروع Flutter عربي لإدارة مصنع الواحه، المندوبين، الإنتاج، المنافذ، الأسعار، المخزون، البرانيك، التحصيل والمرتجعات.

## مرجع المتطلبات

راجع [`PROJECT_SPEC.md`](PROJECT_SPEC.md) للحصول على المواصفات الوظيفية الكاملة، بما فيها واجهتا المندوب والإدارة، صلاحيات المدير والمحاسب والإنتاج ومسؤولي المنافذ، السياسات السعرية، الإنتاج الفعلي والتوزيع النسبي، حسابات المنافذ والمرتجعات.

## الوضع الحالي

يتضمن المشروع أساس Flutter ووحدة السياسات السعرية، وأدوار المدير والمحاسب والإنتاج ومسؤول منفذ المصنع ومسؤول المنفذ الخارجي والمحصّل والموزع. تشمل الترحيلات دورة أولية للطلبات والإنتاج بالتوزيع النسبي والتسليم والمخزون التشغيلي والمرتجعات وحركات البرانيك، إضافة إلى الكتالوج والوصفات المؤرخة وعزل البيانات المالية حسب الدور. هذه ليست بديلًا عن مراجعة واعتماد إجراءات التشغيل قبل الاستخدام الفعلي؛ ما زالت وظائف مثل التحويلات والجرد والإيصالات والتسويات التفصيلية والإشعارات والتصدير بحاجة إلى استكمال.

## إعداد قاعدة البيانات

1. أنشئ مشروع Supabase.
2. طبّق ملفات الترحيل الموجودة في `supabase/migrations/` بالترتيب، دون إعادة تشغيل migrations مطبقة.
3. أضف بيانات الكتالوج الأولية (الأصناف، أنواع العملاء، مواقع الاستلام، المنافذ، المندوبون وروابطهم بالمنافذ) عبر المسارات الإدارية.
4. أنشئ حساب المدير واضبط صلاحياته من مسار موثوق؛ تعديل الأدوار والارتباطات محصور بإجراء إداري في قاعدة البيانات.
5. اختبر مخطط قاعدة البيانات بسياسات RLS باستخدام `supabase test db` قبل إدخال بيانات تشغيلية.

تستخدم بيئة التطوير المحلية `supabase/config.toml` والترحيلات الموجودة في `supabase/migrations/`. شغّل `supabase start` ثم `supabase test db` للاختبار المحلي. لا تربط بيئة الاختبار بمشروع بعيد ولا تضع مفاتيح الخدمة في التطبيق.

## التشغيل

يتطلب Flutter 3.19 أو أحدث. أنشئ مجلدات التشغيل مرة واحدة إن لم تكن موجودة:

```powershell
flutter create --platforms android,web .
flutter pub get
flutter run -d chrome --dart-define=SUPABASE_URL=https://YOUR_PROJECT.supabase.co --dart-define=SUPABASE_ANON_KEY=YOUR_ANON_KEY
```

لأندرويد استخدم قيم `--dart-define` نفسها مع جهاز/محاكي Android. لا تضع مفتاح `service_role` داخل تطبيق العميل.

## ملاحظة

لم يُثبت بعد أن جميع الوظائف في `PROJECT_SPEC.md` منفذة. راجع حالة التنفيذ والاختبارات قبل استخدام النظام في عمليات المصنع الحقيقية.

## تطبيقان من نفس المشروع

- **تطبيق المندوب** (`lib/main_distributor.dart`): تسجيل برقم الهاتف والاسم والمنفذ، ثم انتظار موافقة المدير.
- **تطبيق الإدارة** (`lib/main_admin.dart`): مدير ومحاسب ومنفذ المصنع والمنافذ والإنتاج، ويظهر لكل دور ما يخصه فقط.

```powershell
flutter run -d chrome -t lib/main_distributor.dart --dart-define=SUPABASE_URL=... --dart-define=SUPABASE_ANON_KEY=...
flutter run -d chrome -t lib/main_admin.dart --dart-define=SUPABASE_URL=... --dart-define=SUPABASE_ANON_KEY=...
```

قبل التجربة: في Supabase اذهب إلى Authentication ← Sign In / Providers ← Email وعطّل **Confirm email**، لأن المندوب يسجّل برقم هاتفه (يتحول داخليًا إلى بريد لا يصله شيء). بيانات البداية (المنافذ الثلاثة) في `supabase/seed.sql`.

### تشغيل بدون كتابة المفاتيح يدويًا

ملف `env.json` في جذر المشروع يحتوي رابط المشروع والمفتاح العام (anon). هذا المفتاح مصمم ليكون داخل التطبيق، ولا تضع فيه مفتاح `service_role` أبدًا.

```powershell
flutter run -d chrome -t lib/main_distributor.dart --dart-define-from-file=env.json
flutter run -d chrome -t lib/main_admin.dart --dart-define-from-file=env.json
```
